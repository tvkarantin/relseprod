# Интеграция с Deepgram Speech-to-Text

В Reels Finder добавлена опциональная интеграция с **Deepgram Pre-Recorded Speech-to-Text API** для получения точной расшифровки речи из уже импортированных Instagram Reels.

## Архитектура и принципы

1. **Опциональная интеграция**: Приложение полностью запускается без `DEEPGRAM_API_KEY`. Отсутствие ключа вызывает ошибку только при попытке запустить расшифровку (`503 DEEPGRAM_NOT_CONFIGURED`).
2. **Безопасность API-ключа**:
   - Ключ хранится только в локальном `.env` и никогда не попадает во frontend, в репозиторий или в логи.
   - Запросы к Deepgram выполняются исключительно на бэкенде через `httpx`.
   - В заголовках запроса используется стандартный формат `Authorization: Token <DEEPGRAM_API_KEY>`.
   - Ключ никогда не передается в URL, не логируется и не возвращается в ошибках API.
3. **Разница между Caption и Transcript**:
   - `caption` — оригинальное описание Instagram-публикации (пост/рилс).
   - `transcript` — точная расшифровка речи, полученная из аудиодорожки видео через Deepgram.
   - Эти поля хранятся и отображаются раздельно; `transcript` никогда не перезаписывает `caption` и наоборот.
4. **Транскрибация без перевода**:
   - Deepgram на этом этапе выполняет только распознавание речи (speech-to-text). Автоматический перевод на русский язык и разбиение на хук/основную часть/CTA **не реализовывались** и не имитируются.

## Переменные окружения (`apps/api/.env`)

```ini
DEEPGRAM_API_KEY=
DEEPGRAM_BASE_URL=https://api.deepgram.com/v1
DEEPGRAM_MODEL=nova-3
DEEPGRAM_LANGUAGE=multi
DEEPGRAM_TIMEOUT_SECONDS=180
DEEPGRAM_SMART_FORMAT=true
DEEPGRAM_UTTERANCES=true
DEEPGRAM_PARAGRAPHS=true
DEEPGRAM_NUMERALS=true
DEEPGRAM_PUNCTUATE=true
```

## Модель данных (`ReelTranscription`)

Результаты транскрибации хранятся в отдельной таблице `reel_transcriptions`, связанной с `reels` через каскадное удаление (`ondelete="CASCADE"`). Один рилс имеет ровно одну актуальную запись расшифровки (`unique constraint` на `reel_id`).

Статусы (`TranscriptionStatus`):
- `queued` — задача поставлена в очередь;
- `processing` — Deepgram выполняет распознавание;
- `completed` — расшифровка успешно завершена;
- `failed` — ошибка при обработке.

## API Endpoints

- `POST /api/v1/reels/{reel_id}/transcription` — создать задачу транскрибации (возвращает `HTTP 202 Accepted`).
- `GET /api/v1/reels/{reel_id}/transcription` — получить текущий статус и результат.
- `POST /api/v1/reels/{reel_id}/transcription/retry` — повторить неудачную транскрибацию (`status == failed`, возвращает `HTTP 202 Accepted`).

## Поведение Frontend и интеграция с редактором

1. На странице рилса (`ReelDetailsPage`) добавлен блок управления расшифровкой (`ReelTranscriptionControls`).
2. **Polling**: TanStack Query опрашивает endpoint каждые 2500 мс пока статус `queued` или `processing`. После завершения опрос автоматически прекращается, а кэш инвалидируется.
3. **Ручной перенос в сценарий**:
   - Пользователь может посмотреть расшифровку, скопировать её в буфер обмена (`navigator.clipboard`) или перенести её в поле «Основная часть» («script»).
   - Перенос **никогда не выполняется автоматически**.
   - Если поле «Основная часть» уже содержит текст, система показывает модальное окно подтверждения («Основная часть уже содержит текст. Заменить её расшифровкой?»).
   - Поля «Хук», «Призыв к действию», «Заметки» и «Статус» не затрагиваются.
   - Изменения отмечаются как несохраненные (dirty), и пользователь нажимает существующую кнопку «Сохранить».

## Известные ограничения

- **Протухание URL**: Ссылки на видео в Instagram (`video_url`) со временем устаревают. Если ссылка протухла, Deepgram вернет ошибку, и потребуется повторный импорт конкурента.
- **Только распознавание**: На данном этапе Deepgram выполняет распознавание речи, а языковой перевод и интеллектуальный разбор на хук/тело/CTA не производятся.
