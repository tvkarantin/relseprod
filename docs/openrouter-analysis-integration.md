# Интеграция с OpenRouter для AI-анализа Рилсов

## Назначение

Данная интеграция использует REST API OpenRouter для перевода готовых расшифровок Рилсов (Deepgram transcriptions) на русский язык и их структурного анализа. Анализ разбивает произнесённую речь на смысловые блоки: хук, основная часть, заключение и призыв к действию (CTA).

Важно отметить, что **OpenRouter не выполняет транскрибацию**. Транскрибация речи по-прежнему осуществляется через Deepgram, а OpenRouter обрабатывает уже готовый текст. 

## Модель

Для обработки используется исключительно бесплатная модель `openai/gpt-oss-120b:free`. Суффикс `:free` означает, что используется бесплатная версия API-интерфейса OpenRouter для данной модели. 

Платный fallback отключен и автоматический переход на платную модель не производится. Модель может быть заменена в будущем через переменную окружения `OPENROUTER_MODEL`, но замена на платную версию никогда не происходит автоматически.

Ограничения бесплатной модели:
1. Модель может быть временно недоступна (503).
2. Бесплатная модель имеет строгие ограничения на запросы (Rate Limited 429).
3. Состав бесплатных моделей в OpenRouter может меняться со временем.

## Структурный разбор и JSON Schema

Ответ модели возвращается строго в формате JSON, соответствующем объявленной `JSON Schema`. Формат ответа гарантирует наличие исходного языка, полного перевода на русский, темы, краткого содержания и объектов структурных частей сценария (hook, mainPart, conclusion, cta).

Для защиты от prompt injection:
1. Исходный транскрипт передается в `user` message.
2. `system` prompt четко указывает на то, что транскрипт является недоверенными пользовательскими данными, а не инструкциями.
3. Модели запрещено выдумывать маркетинговые сценарии или таймкоды.

## Вычисление таймкодов

Модель не возвращает таймкоды самостоятельно, так как LLM плохо справляются с расчетами времени. Вместо этого модель возвращает `sourceUtteranceIndexes` — индексы фраз (`utterances`), предоставленных в запросе. 
Затем бэкенд вычисляет фактическое время старта и окончания (`start` и `end`) для каждого блока на основе исходных временных меток фраз (utterances) из Deepgram.

## База данных: ReelAnalysis

Анализ сохраняется в отдельную ORM-модель `ReelAnalysis`.
Таблица не переопределяет пользовательские данные автоматически. Анализ привязан к транскрибации `transcription_id` и к `reel_id`.
При удалении рилса каскадно удаляется его анализ и транскрибация.

Не хранятся:
- сырой ответ OpenRouter
- промежуточные рассуждения (reasoning)
- токены авторизации (API ключи)

## Background Task

AI-анализ выполняется в фоне (через FastAPI `BackgroundTasks`).
1. Запуск: `POST /api/v1/reels/{reel_id}/analysis` возвращает HTTP 202.
2. Клиент (frontend) поллит (polling) статус задачи через `GET /api/v1/reels/{reel_id}/analysis`.

## Ручное применение к ReelContentEditor

Анализ позволяет пользователю просматривать результат перевода и структуры, но не перезаписывает поля формы автоматически.
С помощью кнопки "Применить к сценарию" открывается диалог, в котором можно выбрать, какие именно части (хук, основная часть, CTA) применить. 
Применение только изменяет локальное состояние (dirty) React Hook Form, требуя от пользователя вручную нажать кнопку "Сохранить" для отправки PUT запроса.

## Безопасность

- `OPENROUTER_API_KEY` задается через переменные окружения (.env).
- API-ключ не передается во фронтенд и не сохраняется в истории коммитов.
- Заголовки `Authorization` не логируются.
