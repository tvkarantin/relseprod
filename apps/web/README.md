# Reels Finder — frontend

React-интерфейс Reels Finder. Работает только с локальным backend
(FastAPI + SQLite) и **никогда не обращается к Apify напрямую**.

## Технологии

| Компонент | Назначение |
|---|---|
| React 18 + TypeScript | UI и типизация |
| Vite 6 | dev-сервер и сборка |
| React Router 6 | маршрутизация |
| TanStack Query 5 | загрузка данных, кэш, polling |
| React Hook Form + Zod | формы и валидация |
| Vitest + Testing Library | тесты |
| ESLint | линтер |

Крупные UI-библиотеки намеренно не используются: тёмная тема реализована
собственным CSS в `src/styles.css`.

## Установка и запуск

```powershell
cd apps/web
npm install
Copy-Item .env.example .env
npm run dev
```

Приложение откроется на <http://localhost:4173>.

**Backend должен быть запущен** — см. [`apps/api/README.md`](../api/README.md).

### Переменные окружения

`apps/web/.env` создаётся копированием `.env.example`:

```
VITE_API_URL=http://localhost:8000/api/v1
```

⚠️ Во frontend **не должно быть никаких секретов**. `APIFY_API_TOKEN` живёт
только в `apps/api/.env` на стороне сервера. Всё, что попадает в `VITE_*`,
видно в браузере.

## Маршруты

| Маршрут | Экран |
|---|---|
| `/` | Обзор: реальные счётчики и быстрые действия |
| `/competitors` | Конкуренты: добавление, импорт, удаление |
| `/reels` | Библиотека импортированных рилсов |
| `/reels/:reelId` | Просмотр рилса и редактор сценария |
| `/my-reels` | Рилсы, для которых начат сценарий |
| `*` | 404 |

Разделы без backend-функциональности (календарь, шаблоны, темы, медиа,
аналитика, теги, интеграции) в навигации отсутствуют.

## Зависимости от API

| Экран | Endpoints |
|---|---|
| Обзор | `GET /dashboard/summary` |
| Конкуренты | `GET/POST /competitors`, `DELETE /competitors/{id}`, `POST /competitors/{id}/parse`, `GET /jobs/{id}`, `POST /jobs/{id}/retry` |
| Библиотека | `GET /reels`, `GET /competitors` |
| Рилс | `GET /reels/{id}`, `PUT /reels/{id}/content` |
| Мои рилсы | `GET /reels/my` |

## API-клиент

`src/api/client.ts` — единственная точка выхода в сеть:

- общий `VITE_API_URL`;
- JSON-заголовки;
- разбор единого формата ошибок в типизированный `ApiError`
  (`code`, `status`, `details`);
- поддержка `AbortSignal` (React Query отменяет устаревшие запросы);
- таймаут 20 секунд;
- сетевой сбой превращается в понятное сообщение, а не в необработанный reject;
- никаких токенов и прямых обращений к Apify.

## Кэш TanStack Query

Ключи собраны в `src/api/queryKeys.ts`. После мутаций выполняется точечная
инвалидация, весь кэш никогда не очищается:

| Действие | Инвалидация |
|---|---|
| Создан конкурент | `competitors.*`, `dashboard.summary` |
| Удалён конкурент | `competitors.*`, `reels.*`, `dashboard.summary` |
| Импорт завершён | `competitors.*`, `reels.*`, `dashboard.summary` |
| Сохранён сценарий | точечное обновление `reels.details` + инвалидация `reels.list`, `reels.my`, `dashboard.summary` |

## Поиск

- поле поиска синхронизировано с URL: `/reels?search=маркетинг&competitor_id=1&page=2`;
- debounce 400 мс;
- изменение поиска или фильтра сбрасывает `page` на 1;
- пустые параметры в URL не пишутся;
- reload и кнопки «назад/вперёд» браузера сохраняют состояние;
- поиск на стороне сервера по описанию, username конкурента и всем полям
  сценария; регистр не учитывается, в том числе для кириллицы.

## Пагинация

Серверная, по 20 элементов. Показываются номера страниц с сокращением
(`1 … 4 5 6 … 42`), кнопки «Назад»/«Вперёд» отключаются на границах.
Сортировка фиксированная (`published_at DESC`), переключателя нет.

## Polling задачи импорта

`src/hooks/useJobPolling.ts`:

- опрашивает `GET /jobs/{id}` каждые 2,5 секунды;
- работает **только** для статусов `queued` и `running`;
- останавливается при `completed`/`failed` и при размонтировании;
- один интервал на задачу — параллельные таймеры не создаются;
- переживает временные сетевые ошибки (2 повтора);
- прогресс берётся из ответа backend и **не имитируется** на клиенте;
- после завершения обновляет списки рилсов, конкурентов и счётчики.

## Автосохранение сценария

`src/hooks/useAutosave.ts`, задержка **800 мс**.

Запрос уходит, только если данные прошли Zod-валидацию, отличаются от
последнего сохранённого состояния и такой же запрос не выполняется прямо
сейчас.

Гарантии:

1. первичная загрузка не отправляет `PUT`;
2. быстрый ввод даёт один запрос, а не запрос на символ;
3. новое изменение отменяет предыдущий debounce;
4. **устаревший ответ не может затереть новый ввод** — запросы версионируются,
   применяется только ответ на последний;
5. ошибка не стирает введённый текст;
6. после ошибки доступна кнопка «Сохранить» для ручного повтора;
7. при переходе к другому рилсу форма пересоздаётся (`key={reel.id}`).

Состояния рядом с редактором: «Сохранено», «Есть изменения», «Сохранение…»,
«Ошибка сохранения». Toast на каждое автосохранение не показывается.

Если есть несохранённые изменения, попытка закрыть или перезагрузить вкладку
вызывает системное предупреждение браузера (`beforeunload`). Когда всё
сохранено, предупреждение не появляется.

## Fallback для медиа

Обложка: `thumbnailUrl` → нейтральный placeholder (обработка `onError`).
Видео: `<video controls>` с `poster` → обложка → placeholder. Ссылка «Открыть
в Instagram» доступна всегда. Autoplay со звуком не используется, обход CORS не
выполняется — недоступное видео не ломает страницу. Случайные стоковые
изображения не подставляются.

## Тесты

```powershell
npm run test
```

Покрыты: API-клиент (успех, ошибки, сеть, abort, таймаут), список и добавление
конкурентов, дубликат, запуск импорта, polling, completed/failed, retry,
удаление с подтверждением, состояния библиотеки, поиск с debounce, фильтр,
пагинация, редактор (загрузка, debounce 800 мс, отсутствие PUT на初 загрузке,
сохранение, ошибка, ручной повтор, лимиты длины, статусы, защита от устаревшего
ответа), утилиты форматирования.

Настоящий backend в unit-тестах не вызывается — API замокан.

## Доступность

Каждое поле имеет `<label>`, иконочные кнопки — `aria-label`, действия — реальные
`<button>`, ссылки — `<a>`. Диалог подтверждения закрывается по Escape и
получает фокус. Ошибки связаны с полями через `aria-describedby`, есть видимый
focus-state и `aria-live` для статусов.

## Безопасность

- токенов во frontend нет;
- обращений к Apify из браузера нет;
- пользовательский текст и описания рендерятся как текст;
  `dangerouslySetInnerHTML` не используется;
- все внешние ссылки — `target="_blank"` с `rel="noopener noreferrer"`;
- изображения загружаются с `referrerPolicy="no-referrer"`.

## Ограничения

- нет авторизации: интерфейс рассчитан на локальный запуск;
- нет аналитики, графиков, тегов, пользовательской сортировки и сложных
  фильтров;
- нет скачивания видео и обложек — показываются только ссылки Instagram;
- «Мои рилсы» — простые вкладки по статусам, без Kanban и drag-and-drop;
- CDN-ссылки Instagram живут недолго: у старых рилсов видео и обложка могут не
  открыться, в этом случае показывается placeholder;
- фоновые задачи выполняются в процессе backend, поэтому после его перезапуска
  незавершённый импорт останется в статусе `running`.
